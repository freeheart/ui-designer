# 品评 rubric

品评（critique）的目标不是「评价好看」，而是**指出影响可用性/可读性/一致性的具体问题，
并给出可直接执行的最小修复**。一条好 finding 应该让用户能点一下「应用建议」就变好。

品评模式**不修改设计稿**：只返回文字 + findings（可带 `suggestedOps`）。改稿请用改稿模式。

## 评审顺序（先整体后局部）

1. **目标与信息层级**：首屏 3 秒内能否看出「这是什么产品、我现在能做什么」？主 CTA 是否唯一且
   视觉最重？标题层级（size/weight/color）是否形成清晰的三级节奏？
2. **布局与对齐**：是否有统一的内容边距与栅格？左右/上下边距是否一致？元素是否对齐到同一条
   基线/边线？卡片间距是否成体系（8pt 网格：4/8/16/24/32/48）？
3. **间距节奏**：相关元素靠得近、无关元素拉得开（proximity）；组内 gap 一致；不要出现 3px、
   13px 这种游离值。
4. **颜色与对比度**：正文与背景 ≥ 4.5:1，大字号/粗体 ≥ 3:1；主色只用于行动与强调，不要
   大面积铺；深色主题注意 surface/surface2 的层次差是否可分辨。
5. **字体与可读性**：字号阶梯不超过 4–5 级；正文行高 ≥ 1.5；长文本有最大宽度；全大写/字距
   只在标签用。
6. **一致性**：圆角、描边、阴影、图标线宽、按钮高度是否成系统；同类卡片是否同一套参数。
7. **状态与完备性**：空状态/加载/错误/禁用/选中态是否缺失；长文案是否溢出；列表是否考虑
   0/1/N 条；表单是否给出必填/错误提示位置。
8. **可访问性**：点击区域 ≥ 32–44px；颜色不是唯一信息载体（状态需文字/图标）；图标按钮有
   可理解语义；对比度不要只靠 hover 变化。
9. **内容与文案**：按钮动词化、具体（「保存草稿」而非「提交」）；数字有单位/格式；避免
   占位文案 Lorem ipsum 遗留在交付稿里。
10. **平台适配**：移动端宽度下元素是否越界、文字是否折行错位；桌面端内容是否过宽。

## 严重度

| severity | 判定 |
|---|---|
| `high` | 影响可用性/可读性：对比度不足、主 CTA 不突出、内容越界、关键信息缺失 |
| `medium` | 一致性与节奏：间距/圆角/字号不规范、层级不清晰、同类组件参数不一致 |
| `low` | 打磨：微调对齐、补充留白、文案润色、可选的视觉增强 |

一次给 **3–6 条**，覆盖不同维度，避免 6 条都在说对比度。每条都要有 `targets`
（尽量精确到节点 id）和可选的 `suggestedOps`（1–3 个最小修复 op，不能改变整体结构）。

## findings 结构

```jsonc
[
  {
    "id": "f-1",
    "severity": "high",
    "title": "主按钮对比度过低",
    "detail": "「查看全部」用 primary 色文字放在 surface 上，对比度约 3.1:1，低于正文要求的 4.5:1；建议改为更亮的主色或加背景。",
    "targets": ["n-more"],
    "suggestedOps": [
      { "op": "set", "id": "n-more", "path": "style.font.color", "value": "text" }
    ]
  }
]
```

- `targets`：节点 id 数组；没有明确目标时给 `[]` 并在 detail 里说明位置。
- `suggestedOps`：必须能通过 `applyOps` 校验；宁可给 0 个也不要给会让设计稿校验失败的 op。
  适合自动修复的：改颜色/字号/字重/间距/圆角/填充/文案。不适合的（布局重排、删模块）留空，
  在 detail 里说明建议。
- 编辑器会把每条 findings 渲染成卡片：严重度色条 + 标题 + 说明 + 可点击的 target 芯片 +
  「应用建议」按钮。targets 必须真实存在，否则芯片无法聚焦节点。

## 常见问题模式（可直接套用）

- **对比度**：`muted` 文字（#94a3b8）放在 `surface`（#111827）上约 6.3:1 合格；
  放在 `surface2` 上仍合格；但 `primary`（#6366f1）当正文色通常只有 3–4:1，需换 `text` 或加底。
- **越界**：节点 x<0、y<0、x+w>画板宽、y+h>画板高（`ops.mjs --summary` 会列）。
- **点击区域**：按钮/输入框高 <32、图标按钮 <32×32。
- **层级不足**：页面标题与卡片标题同字号同字重；主 CTA 与次按钮同权重。
- **间距游离**：出现 10/12/13/20 等不在 4/8/16/24/32/48 上的外边距。
- **重复信息**：标题里已有页面名，又用 breadcrumb/标签重复一遍。
- **占位残留**：头像 initials 是「AI」、图片是棋盘格、表格是示例数据却当正式交付。
- **状态缺失**：表格没有空状态；表单没有错误样式；按钮没有 disabled 态（可用多画板表达）。

## 与自动告警的关系

服务端在品评请求里会附带 `summarizeSpec` 的机械告警（overflow / contrast / target-size）。
这些是**兜底**，不要简单复述：要么给出更深的设计判断，要么把机械告警转成可执行的修复建议
（例如「把 n-more 的文字色改成 text，对比度从 3.1 提到 8.9」）。

## Agent 通道回复品评结果

```powershell
node scripts/agent-bridge.mjs reply --design designs/home/design.json `
     --id req-xxxxxxxx --message "共 4 条建议，已按严重度排序。" --findings findings.json
```

`findings.json` 是上面的数组或 `{ "findings": [...] }`。品评请求不要带 `--ops`。
